- Background jobs gain per-host control for apps running on more than one server.
  - `set(jobsMaxConcurrentPerHost = n)` caps how many jobs one server runs at once. The default `0` means no cap, which is today's behaviour. The cap is enforced in the worker, so `wheels jobs work`, `processNext()` and the new `JobRunner.tick()` all respect it. The count and the claim happen under one lock per host, so two polls can't both take the last slot.
  - `new wheels.JobRunner().drain(expiresInSeconds)` / `.resume()` stop a server from starting new jobs while the jobs it is already running finish (for deploys). Reaping continues, and an expired drain lifts itself.
  - `JobRunner.tick(queues, maxConcurrent, timeout, maxJobs)` is one round for a scheduled task: it registers the server in the new `wheels_job_hosts` table (auto-created, never inside a transaction), reaps, and runs up to `maxJobs` jobs unless the server is draining or full. `JobRunner.status()` reports the server's running jobs, cap and drain.
  - A server is identified by the host name recorded in `wheels_jobs.claimedBy`. Set `set(jobsHostName = "...")` when several app servers share one machine, so each gets its own cap and drain. `processNext()` results gain `capped` and `draining`. ([#4480](https://github.com/wheels-dev/wheels/issues/4480))
