- An empty string in a `where` value now binds as a real empty string instead of SQL NULL, so `count(where="col = ''")` matches rows that store `''`, and `col <> ''` / `col != ''` match every other non-NULL row. Before, all three compared against NULL and matched nothing. This applies to `findAll()` / `count()` and the other finders, `updateAll()` / `deleteAll()` `where` conditions, dynamic finders such as `findOneByName("")` and the query builder, so `updateAll()` and `deleteAll()` with such a condition now change those rows. Use `IS NULL` / `IS NOT NULL` (or `whereNull()` / `whereNotNull()`) to match NULL. Lookups keyed on request values, such as `findOne(where="token = '#params.token#'")` or `findOneByToken(params.token)`, now match a row that stores `''` when the value is empty, so check required values first. The unquoted `NULL` keyword still binds as NULL; an empty value whose column binds as a number, date, time or boolean still matches nothing (SQLite binds its text datetimes as strings, so they follow the new behaviour); and Oracle, which stores `''` as NULL, is unchanged (#4055)
