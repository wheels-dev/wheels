- Query builder: `offset()` is now applied. It was stored but never passed to the finder, so `model("User").orderBy("id").limit(10).offset(20).get()` returned rows 1-10. `get()`/`findAll()` and `first()`/`findOne()` now emit SQL `OFFSET` (with `limit()` as the row count, or every remaining row when no limit is set) and default to primary-key order when no `orderBy()` is given; on SQL Server the limit is clamped to the rows left after the offset so the last page is correct. `count()`, `exists()`, `updateAll()`, `deleteAll()`, `findEach()` and `findInBatches()` ignore the offset. `afterFind` callbacks now also run on query results fetched with an offset.
