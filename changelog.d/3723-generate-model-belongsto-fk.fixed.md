- `wheels generate model <Name> --belongsTo=<Parent>` (CLI, `g` alias and the MCP `generate` tool) now adds the foreign-key column to the generated migration, as `scaffold` and `api-resource` already did — `<parent>_id` when `useUnderscoreReferenceColumns=true` (the `wheels new` default), `<parent>Id` otherwise. The migration previously had no FK column, so the association's default foreign key named a missing column and `wheels seed` failed. A column you list yourself, in either shape, is not duplicated (#3723)
