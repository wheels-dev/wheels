- The test runner accepts deterministic duration-weighted shard inputs — `?shards=N&shard=K&shardWeights=<url-encoded JSON>` for small scopes (encoded weights capped at 6000 chars) or `?shards=N&shard=K&shardWeightsFile=1` for the full suite (reads a size-capped `tests/shard-weights.json` from the app root, because full-suite weights exceed Adobe's request-line limit) — with a new `wheels.wheelstest.ShardPlanner` using LPT partitioning. Shards are capped at 64, invalid inputs return HTTP 400 (including weights without `shards > 1`), and the payload reports `bundlesSelected`, `shardCount` and `shardIndex`. This is a prototype exposed only through the runner, with no CLI flags yet, and each shard still requires its own app instance and database (#4629)
