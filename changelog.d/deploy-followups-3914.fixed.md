- `wheels deploy` follow-ups: the `deploy init` Dockerfile no longer hard-codes `WHEELS_DATASOURCE=app` (the app's own datasource name applies), ships `db/`, and links the current guides; `deploy registry login` without `registry.username` fails with a clear error instead of running `docker login -u ''`; a missing or empty `config/deploy.yml` says so (and points at `wheels deploy init`) instead of a raw file error; unknown `proxy.*` keys and a non-boolean `proxy.ssl` are rejected; `deploy app details` / `app live` / `app maintenance` no longer require `--release`, and the verbs that do ask for `--release`; `deploy config` prints proxy, env (secret names only), accessories, ssh and builder too; and the deploy guides no longer call `setup` an alias of `deploy` (#3914)
