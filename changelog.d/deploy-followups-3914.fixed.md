- `wheels deploy` follow-ups: the `deploy init` Dockerfile no longer hard-codes `WHEELS_DATASOURCE=app` (the app's own datasource name applies) and links the current guides; the local `db/*.sqlite` files are no longer copied into the image (the image gets an empty `db/`, and the generated `.dockerignore` excludes SQLite files), and `deploy init` tells a SQLite app that production starts with an empty database and how to run migrations on boot; `deploy registry login` without `registry.username` fails with a clear error instead of running `docker login -u ''`; a missing or empty `config/deploy.yml` says so (and points at `wheels deploy init`) instead of a raw file error; unknown `proxy.*` keys and a non-boolean `proxy.ssl` are rejected; `deploy app details` / `app live` / `app maintenance` no longer require `--release`, and the verbs that do ask for `--release`; `deploy config` prints proxy, env (secret names only), accessories, ssh and builder too, and shows a `registry.password` entry only when it names a key in `.kamal/secrets`; and the deploy guides no longer call `setup` an alias of `deploy` (#3914)
