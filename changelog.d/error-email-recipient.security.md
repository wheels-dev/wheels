- Error emails no longer go to an address derived from the request. The framework used to default `errorEmailAddress` to `webmaster@` plus the last two labels of the Host header of whichever request started the application, and production turns `sendEmailOnError` on. So a request with a crafted Host at a cold start could redirect every later error email to a domain of the requester's choosing. `errorEmailAddress` now defaults to `""`, and with no recipient configured no error email is sent: Wheels writes a one-time warning to `wheels.log` instead. **Apps that relied on the default must set `errorEmailAddress` (or `errorEmailToAddress`) explicitly.** The sender falls back to the recipient when `errorEmailFromAddress` is not set. ([GHSA-8gcv-3v9h-7gj2](https://github.com/wheels-dev/wheels/security/advisories/GHSA-8gcv-3v9h-7gj2))
