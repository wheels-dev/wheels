- `wheels deploy` can run the database migrations once per deploy, on one host. Add `migrate: true` (or `migrate: {host: <host>, timeout: <seconds>}`) to `config/deploy.yml`. The migrate host (default: the first host of the first role, which must be proxy-fronted) boots and cuts over first, with `WHEELS_MIGRATE_ON_BOOT=true` and a longer health-check timeout (default 300s). Every other app container gets `WHEELS_MIGRATE_ON_BOOT=false`, so hosts sharing a database no longer all migrate at start. A migration that fails stops the deploy before any host cuts over. Without the block nothing changes. Apps with only job/worker roles are refused for now (#4063).
- New `set(migrateOnBoot=true)`: migrate to the latest version when the application starts, and fail the start (`Wheels.BootMigrationFailed`, written to the wheels log) when a migration is still pending afterwards. A boolean `WHEELS_MIGRATE_ON_BOOT` environment variable overrides both `migrateOnBoot` and `autoMigrateDatabase`: `true` migrates strictly, `false` never migrates at start. Without it, `autoMigrateDatabase` behaves exactly as before (#4063).
