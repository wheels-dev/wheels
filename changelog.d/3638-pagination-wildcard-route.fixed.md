- `paginationLinks()` no longer adopts an ambiguous ambient route name, so a paginated `index` action reached through the catch-all `wildcard()` route (the default scaffolded routes) no longer throws `Wheels.RouteNotFound` — which rendered as a whole-page 404 in production, with nothing logged, because the route error path aborts. The ambient `request.wheels.params.route` name from the #942 fix is now adopted only when it resolves to a single named route; the `wildcard` name registers one candidate per method x pattern, and `paginationLinks()` supplies neither a method nor the route's path variables, so `$findRoute()` could never disambiguate it. Falling through to the controller/action URL produces the same link the wildcard route serves (#3638)
- `paginationLinks(route="")` is now a real opt-out: an explicitly empty `route` is treated as "no route" instead of being passed to `$findRoute()`, which threw `Wheels.RouteNotFound` for the empty name and gave applications no way to suppress the ambient-route adoption in the meantime (#3638)
