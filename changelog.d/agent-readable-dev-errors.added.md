- In the `development` environment with `showErrorInformation` on (its default there), an error response asked for as JSON (`Accept: application/json` or `?format=json`) is now the structured payload the error page's Copy button builds: exception type and message, suggested action, location, source snippet and classified stack, plus `statusCode`. `Accept: text/markdown` (without `application/json`) or `?format=md` returns the same content as Markdown. Both use the error page's status code and drop anything the request wrote before it failed. Testing, maintenance and production responses are unchanged. The payload's location now picks an app frame that is the throw site itself, as the error page does, and its JSON keys keep their case on every engine.
