- The `channel` `DatabaseAdapter.poll()` no longer returns events out of publish order when two events share a `createdAt` timestamp — common on SQL Server, MySQL, and Oracle, whose datetime columns round to coarse ticks, and possible anywhere on a same-millisecond publish. Events now carry a database-native monotonic sequence (SQLite uses its built-in `rowid`; an unrecognised database falls back to `createdAt` + `id`), `poll()` orders by it, and `lastEventId` resumes strictly after the referenced event — which also stops a same-tick event published before it from being re-delivered, and falls back to the `since` window when the referenced event has already been cleaned up. Existing `wheels_events` tables gain the column automatically (#4099)
