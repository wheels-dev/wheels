- The password-less `/wheels` development endpoints (the GUI pages, docs viewer, test runners, and the deprecated HTTP MCP) now require the request's `Host` header to name the local machine, and reject a non-loopback `X-Forwarded-For` hop, before any handler runs. This is a Host-level gate at the public-component dispatch: it does **not** check the socket address, so a Wheels dev server reached through a Docker port mapping (where the socket source is the bridge gateway, not loopback) keeps working. `localhost`, any `*.localhost`, `127.0.0.0/8`, and `[::1]` are accepted by default; add other local names with `set(devToolsAllowedHosts="my.host")`. The mutating endpoints keep their existing loopback-socket and CSRF/password checks on top. These endpoints remain blocked entirely in production.
