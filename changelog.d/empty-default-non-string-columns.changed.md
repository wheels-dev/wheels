- Migrations: an empty `default` on a column that is not string-like (`bigInteger`, `binary`, `uniqueidentifier`, `integer`, `decimal`, `float`, `date`…) now means "no default". It renders as `DEFAULT NULL` when the column allows null and as no `DEFAULT` clause on a `NOT NULL` column, in `createTable()`, `addColumn()` and `changeColumn()` alike. Before, `bigInteger` and `uniqueidentifier` produced a bare `DEFAULT` (a syntax error on every database for `NOT NULL` columns, and on PostgreSQL in every case), `binary` produced `DEFAULT ''` (rejected by MySQL), and `DEFAULT NULL NOT NULL` was rejected by MySQL.
