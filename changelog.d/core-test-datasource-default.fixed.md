- The framework test suite (`/wheels/core/tests`) runs in an app made with `wheels new`. `coreTestDataSourceName` used to default to a datasource named after the app's folder (`public`) before `config/settings.cfm` set `dataSourceName`, so the run failed with `Datasource [public] doesn't exist`. It now defaults to the `dataSourceName` the settings set, so the run uses `<datasource>_test`. A `coreTestDataSourceName` that names a datasource that does not exist now gets a 409 explaining how to fix it (set `coreTestDataSourceName`, create the datasource, or pass `?db=`) instead of the engine's error.
- A `coreTestDataSourceName` that differs from `dataSourceName` only in letter case is treated as the app's primary datasource, so the framework suite still uses `<datasource>_test` (datasource names are case-insensitive).
- The 409 responses of the test runners have lowercase keys (`success`, `error`, `message`, `datasource`, `candidate`); on Lucee they were serialized in uppercase.
