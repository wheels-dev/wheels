- A token-gated jobs tick route, `/wheels/jobs/tick`, lets an engine scheduled task, cron job or systemd timer run background jobs inside the app server without a worker process. Each call runs one `JobRunner.tick()` (reap dead workers' jobs, then run jobs up to the per-host cap) and returns a JSON summary; an overlapping call on the same server is skipped. The route is off (404) unless `set(jobsRunnerToken = "...")` is set; every call must send the token in the `X-Wheels-Jobs-Token` header (compared in constant time), or as `?token=` only with `set(jobsRunnerTokenInQuery = true)` for schedulers that can only set a URL (the token then ends up in access logs). Requests carrying a forwarding header (`X-Forwarded-For`, `Forwarded`, `X-Real-IP`, `CF-Connecting-IP`) are refused: the token, not the client's address, is the boundary. It works with `enablePublicComponent = false`. `wheels jobs tick` runs one tick from the command line. ([#4482](https://github.com/wheels-dev/wheels/issues/4482))
