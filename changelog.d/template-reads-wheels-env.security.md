- Apps generated by `wheels deploy init` ran in development mode in production, exposing error details: the generated `config/environment.cfm` hardcoded `set(environment="development")`, so the image's `WHEELS_ENV=production` had no effect. The generated config now reads `WHEELS_ENV`: unset or empty means `development`, and any value other than `development`, `testing`, `maintenance` or `production` stops the app from starting instead of running with development-style error output. `config/settings.cfm` now reads `WHEELS_DATASOURCE` with the app name as its default. This applies to `wheels new` and the `wheels-base-template` download. `wheels info` and the `wheels test` preamble recognise the new `dataSourceName` form. **Existing apps:** templates don't reach an existing app, so replace `config/environment.cfm` with the generated version (see the Environments and Configuration guide), or hardcode `set(environment="production");` on production servers. A `WHEELS_ENV` line in `.env` wins over the process environment, so make sure a production server's `.env` doesn't say `development`. (#3946)
