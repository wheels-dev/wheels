- `LocalDisk` storage driver: an opt-in `resolveSymlinks` config flag (default `false`) that adds a stricter containment check on top of the always-on lexical guard (#3912). When enabled, `$resolve()` canonicalises paths through the filesystem so a symlink planted under `root` that targets outside it is **rejected** with `Wheels.Storage.InvalidKey` instead of followed. The disk runs a one-time behavioural capability probe at construction and **fails closed** with `Wheels.Storage.InvalidConfiguration` on a runtime that can't resolve symlinks (the JVM-free RustCFML engine, or Windows without symlink privilege), rather than silently enabling an ineffective strict mode. Detection is a capability probe, never an engine-name check. ([#4020](https://github.com/wheels-dev/wheels/issues/4020))
