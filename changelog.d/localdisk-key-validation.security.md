- `LocalDisk` storage now validates object keys per path segment instead of rejecting any key that contains `..` anywhere. A legitimate name with two dots inside a segment — `reports/q3..final.pdf`, `a..b.txt`, `v1..2` — can now be stored, while the path-traversal guard is tightened: it rejects any segment that is empty or made only of dots and/or whitespace (`.`, `..`, `...`, `. .`, and — because Windows strips trailing dots and spaces — `.. `), an absolute key (`/etc/passwd`), and a drive-letter prefix (`C:/…`). As defence in depth the resolved path is lexically canonicalised (resolving `./`, `../` and `//`) and confirmed to stay inside the storage root with a trailing-separator compare, so `/root-evil` can't pass as inside `/root`. The containment check is lexical and uniform on every engine including the JVM-free RustCFML; it does not resolve symlinks (a symlink planted under `root` is still followed and trusted, since it requires filesystem access to create, not the storage API). ([#3912](https://github.com/wheels-dev/wheels/issues/3912))
