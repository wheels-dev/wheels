- `LocalDisk` storage now validates object keys per path segment instead of rejecting any key that contains `..` anywhere. A legitimate name with two dots inside a segment — `reports/q3..final.pdf`, `a..b.txt`, `v1..2` — can now be stored, while the path-traversal guard is tightened: it rejects any segment that is made only of dots and/or whitespace (`.`, `..`, `...`, `. .`, and — because Windows strips trailing dots and spaces — `.. `) and any drive-letter prefix (`C:/…`, `C:foo`). Every key stays relative to the root: a leading `/`, a trailing `/`, doubled `//` and a UNC/network prefix (`//server/share`, `\\server\share`) are normalised to a relative key under the root, and keys are never URL-decoded, so `%2e%2e%2f` stays a literal segment and can't turn into `../`. As defence in depth the resolved path is lexically canonicalised (resolving `./`, `../` and `//`) and confirmed inside the root with a trailing-separator compare, so `/root-evil` can't pass as inside `/root`. The containment check is lexical and uniform on every engine including the JVM-free RustCFML; it does not resolve symlinks (a symlink planted under `root` is still followed and trusted — see [#4020](https://github.com/wheels-dev/wheels/issues/4020)).
