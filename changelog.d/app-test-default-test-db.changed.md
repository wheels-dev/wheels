- **Behaviour change:** `/wheels/app/tests` (and `wheels test`) now **default to the `<datasource>_test` database and refuse to run if it is absent**, instead of silently falling back to the primary datasource — so test writes never reach your real database. An app with no `<datasource>_test` that runs its tests gets a clear refusal (HTTP 409 / a red "Test run failed before any spec ran" message) telling you to create the `<datasource>_test` datasource, pass `useTestDB=false` (`wheels test --no-test-db`), or set `allowTestsAgainstPrimaryDatasource=true`. A default `wheels new` (SQLite) app already has a `<name>_test` datasource, so `wheels new` → `wheels test` is unaffected; only apps that configure a datasource without a matching `_test` (e.g. `wheels new --no-sqlite`) need to act. Precedence: an explicit `useTestDB=true` always requires the test database; `useTestDB=false` runs against the primary datasource; and `set(allowTestsAgainstPrimaryDatasource=true)` in `config/settings.cfm` lets an **omitted** flag (e.g. from an older CLI that cannot send `useTestDB=false`) run against the primary datasource with a warning.
