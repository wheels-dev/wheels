- `enqueue()`, `enqueueIn()` and `enqueueAt()` throw `Wheels.Job.EnqueueFailed` when the job cannot be written to the job store, instead of returning `persisted: false`, which callers rarely checked, so failed enqueues went unnoticed. One cause is enqueueing inside a raw `transaction {}` block on another datasource (a tenant's), which some engines refuse; inside a Wheels-managed transaction the write now waits for the commit. If an enqueue is best-effort in your app, wrap it in `try` / `catch (Wheels.Job.EnqueueFailed e)`.
