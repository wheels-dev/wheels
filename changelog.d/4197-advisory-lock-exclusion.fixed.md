- `withAdvisoryLock()` now keeps a second caller out on Lucee and BoxLang with MySQL or PostgreSQL. The database lock belongs to the pooled session that took it, and a second caller in the same application could borrow that idle session, take the lock too, and leave it held after both finished. Callers in one application now wait on an application-server lock first, and the wait for the database lock gets only the time left of `timeout`, so the whole call waits about `timeout` at most. The release is verified against the session recorded when the lock was taken: retried for up to 5 seconds when it ran on another session, then reported with `Wheels.AdvisoryLockReleaseFailed` naming the lock. Another server taking the lock once ours is gone is not reported as a failure (#4197)
