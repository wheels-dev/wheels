- The minimal "Application Error" page shown when Wheels fails to initialize now follows the app's `showErrorInformation` setting once startup has got far enough to set it. When it's on (every environment except `production`, by default), the page shows the root cause in full: type, message, detail, the event and the tag context, with Adobe CF's event-handler wrapper unwrapped. When it's off, the page shows only the pointer to `wheels.log` and **no longer prints the exception message**. A failure before the settings load still shows the bare message, as before. Every value is HTML-encoded. Existing apps must copy the change into their own `public/Application.cfc`: replace `$renderMinimalError()` and `$logStartupFailure()`, and add `$startupFailureShowDetail()`, `$startupFailureDetailHtml()` and `$startupFailureRoot()` from the current `wheels new` template (#3671)
