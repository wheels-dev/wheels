- The minimal "Application Error" page shown when Wheels fails to initialize now follows the app's `showErrorInformation` setting once startup has got far enough to set it. When it's on (every environment except `production`, by default), the page shows the root cause in full: type, message, detail, the event and the tag context, with Adobe CF's event-handler wrapper unwrapped. **Behaviour change:** when it's off, the page shows only the pointer to `wheels.log` and **no longer prints the exception message**, so a production startup failure's text no longer reaches the browser. Set `showErrorInformation` to `true` to see it on the page. The full failure is still written to `wheels.log` in every environment, and that log line now carries the whole tag context (up to 20 frames), not only the first frame. A failure before the settings load still shows the bare message, as before. Every value is HTML-encoded. Existing apps must copy the change into their own `public/Application.cfc`: replace `$renderMinimalError()` and `$logStartupFailure()`, replace `$startupFailureFrame()` with `$startupFailureFrames()`, and add `$startupFailureShowDetail()`, `$startupFailureDetailHtml()` and `$startupFailureRoot()` from the current `wheels new` template (#3671)
