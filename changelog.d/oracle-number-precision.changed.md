- On Oracle, new `t.integer()`, `t.references()` and `id` columns are created as `NUMBER(10)`, new `t.bigInteger()` columns as `NUMBER(19)`, and new `t.boolean()` columns before Oracle 23ai as `NUMBER(1)`, instead of a bare `NUMBER`. They bind and validate as integers, so a new integer column no longer accepts a fractional value. Existing bare `NUMBER` columns keep their current typing, and `changeColumn()` without `precision` keeps a column's current precision, so changing a default or `allowNull` never re-types it (Oracle cannot narrow a populated column); the migrations guide shows how to convert one (#4097)
