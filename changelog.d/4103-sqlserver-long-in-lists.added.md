- On SQL Server 2016+ (database compatibility level 130 or higher), a query whose IN lists would bind more than the 2097 parameters SQL Server accepts now runs: its largest lists of integers, plain decimals, strings and uniqueidentifiers are bound as one parameter each and expanded on the server with `STRING_SPLIT`, every value still bound. Queries within the limit keep their SQL. Any other list (dates, times, float, real, bit, text or binary values, or numbers such as `+5`, `.5` or `1E5`), and databases below compatibility level 130, keep the `Wheels.TooManyParameters` error, whose details now say which lists SQL Server runs as one parameter; long date and time lists are tracked in #4318 (#4103)
