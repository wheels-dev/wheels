- On SQL Server 2016+ (database compatibility level 130 or higher), a query whose IN lists would bind more than the 2097 parameters SQL Server accepts now runs: its largest integer, decimal and string lists are bound as one parameter each and expanded on the server with `STRING_SPLIT`, every value still bound. Queries within the limit keep their SQL. Date and time lists, and databases below compatibility level 130, keep the `Wheels.TooManyParameters` error, whose details now say which lists SQL Server runs as one parameter; long date and time lists are tracked in #4318 (#4103)
