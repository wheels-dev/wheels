- Timestamp values read back from the database are normalized before the framework measures elapsed time against them, fixing Oracle on Adobe CF: the Oracle JDBC driver returns TIMESTAMP columns as `oracle.sql.TIMESTAMP`, which is not a `java.util.Date`, so `IsDate()` rejected it — `RateLimiter`'s database-backed token bucket read every bucket as permanently empty or full, and `JobWorker.getMonitorData()` returned a non-date `oldestPending`. The new `$normalizeDbTimestamp()` helper accepts a CFML date, plain or boxed epoch milliseconds (Adobe + sqlite-jdbc), a `java.util.Date`, Oracle's `oracle.sql.TIMESTAMP` (bridged through `timestampValue()`) and fractional-second datetime strings, and replaces the SQLite-only inline epoch conversion in `JobWorker` (#3649)
