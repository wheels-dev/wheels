- When a run of the framework's own test suite (`/wheels/core/tests`) would use the app's primary datasource, it now needs `<datasource>_test` and ignores `allowTestsAgainstPrimaryDatasource`: without the test datasource the run is refused and `wheels.log` notes that the setting was ignored, because the suite's `populate.cfm` drops and recreates tables. An explicit `useTestDB=false` still runs it on the primary datasource. Runs that pick another datasource (`?db=`, or a `coreTestDataSourceName` that isn't the primary) are unchanged, and app test runs keep honouring the setting.
