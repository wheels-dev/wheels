- `wheels deploy build push` honours `builder.arch` (`--platform`, default `linux/amd64`, so an image built on an arm64 workstation runs on amd64 hosts), `builder.args` (`--build-arg` per entry) and `builder.remote` (builds on the service's buildx builder, which `build create` now creates on that endpoint). The image is labelled `service=<service>`. `builder.arch` takes a list or a comma-separated string, and an entry that isn't a plain platform name (letters, digits, `.`, `_`, `/`, `-`) fails with `Wheels.Deploy.InvalidInput` (#4415)
- `wheels deploy app logs` without `--container` tails each role's newest running container instead of emitting a `docker logs` with no container. `wheels deploy prune images` removes every unused image of the service (`--all`), not only dangling ones, matched by the label `build push` now sets; images built before this release carry no label (#4416)
