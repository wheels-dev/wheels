- The background-job table upgrade no longer re-fires the `wheels_jobs.claimTimeout` `ALTER` on every poll when the database user lacks `ALTER` privilege. `wheels jobs work` builds a fresh `JobWorker` each poll, so a blocked `ALTER` was retried every cycle (log noise plus a failed statement each time). A failed `ALTER` is now recorded in an application-scoped, **time-bounded** memo and the retry backs off for a window (re-probed and re-attempted once it elapses, so a later `GRANT` or manual `ALTER` is still picked up) — never a permanent "gave up" flag. The column-existence probe still runs every call, and a missing/`NULL` `claimTimeout` continues to fall back to the polling worker's timeout. ([#4071](https://github.com/wheels-dev/wheels/issues/4071))
