- CLI commands that fail now exit non-zero, and the MCP tools report them as errors (`isError`), instead of printing a message and reporting success. This covers `wheels generate` refusals (the file already exists, an invalid name, an unknown property or test type, a route that exists) and missing arguments, including a bare `wheels generate`; `wheels create`, `wheels destroy`, `wheels db` and `wheels upgrade` with no arguments; `wheels migrate pretend|forget` without a version; `wheels doctor` with status CRITICAL; `wheels analyze` outside a project; `wheels destroy` of a name that was never generated (it also no longer writes a drop-table migration); `wheels docs` with an unknown action and `wheels docs status` outside a project; a deploy config whose `servers` lists no hosts; and `wheels start --engine=rustcfml` when the port is already in use or the server exits right after starting. Error messages are printed once instead of twice. Scripts that relied on these commands exiting 0 after printing usage now need the arguments they were missing.
