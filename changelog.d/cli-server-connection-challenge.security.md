- The CLI can now prove its dev server with an application-level challenge, as well as OS socket introspection. `wheels start` gives each server a per-start token, readable only by the starting OS user, in its registry directory (`<LUCLI_HOME>/servers/<name>/wheels-cli.token`). Before a command sends anything secret, the CLI checks on that same connection that the server can answer an HMAC challenge bound to the connection's addresses and ports. That lets state-changing commands work where `/proc`, `lsof` and `netstat` can't see the listener. A wrong answer fails closed. A framework without the challenge is verified through the OS as before. No token is issued on Windows, or when the registry directory is group- or world-writable. Port-forwarded setups (`docker-proxy`, `ssh -L`) can't pass the check, just as OS introspection can't prove them (#3769)
