- `wheels reload` against a RustCFML server no longer fails every other run. On the first request after a reload restart, the framework sets `request.cgi` before `onRequestStart`, and RustCFML resolves `IsDefined("cgi.<key>")` against `request.cgi`. The `X-Wheels-Reload-Password` header the CLI sends therefore looked absent, and the reload check never saw it. `public/Application.cfc` now falls back to the raw request headers (`GetHttpRequestData()`) when the `cgi` copy is missing. The password stays header-only, and the reload gate, its rate limit and its constant-time comparison are unchanged. Existing apps: copy the updated header-mapping block from the `wheels new` template into your own `public/Application.cfc` (#3913)
