- `wheels reload` against a RustCFML server no longer fails every other run. The first request after a reload restart runs `onApplicationStart` inside the request, and RustCFML then drops the `cgi.http_*` entries, so the `X-Wheels-Reload-Password` header the CLI sends never reached the reload check. `public/Application.cfc` now falls back to the raw request headers (`GetHttpRequestData()`) when the `cgi` copy is missing. The password stays header-only, and the reload gate, its rate limit and its constant-time comparison are unchanged. Existing apps: copy the updated header-mapping block from the `wheels new` template into your own `public/Application.cfc` (#3913)
