- Model validations: `condition`/`unless` expressions that combine clauses with `&&`/`||` no longer throw `Unsupported operator in condition`. `$evaluateConditionString()` now splits a compound boolean at the top level (quote- and paren-aware, with `&&` binding tighter than `||`) and evaluates each side with the existing single-clause machinery, and it recognises a small whitelist of read-only function calls with arguments, including the idiomatic `StructKeyExists(this, 'property')` and the list predicates `ListFind`/`ListFindNoCase`/`ListContains`/`ListContainsNoCase` (so legacy conditions of the shape `ListFind('a,b,c', this.id)` keep working instead of newly throwing). Previously any such expression fell through to the three-token `$evaluateLogicalExpression()` parser, which read the wrong token as the operator; because 4.1.0 made that path fail closed, the symptom changed from a silently skipped validation to a thrown `Wheels.InvalidValidationCondition` (HTTP 500 on save). Note: a function-call condition outside the whitelist still throws here whereas 4.1.0 silently returned false — see the PR description for that remaining upgrade hazard (#3634)
