- Generated apps no longer prepend blank lines to every response. The per-request and lifecycle event templates (`app/events/onrequeststart.cfm`, `onrequestend.cfm`, `onsessionstart.cfm` and siblings) are `$include`d straight into the response buffer, where a bare `cfscript` block and a trailing newline leaked whitespace before the action's output — enough to make `renderText()` of an XML document ill-formed, since the `<?xml …?>` declaration must be the first byte. The templates are now wrapped in `cfsilent` with no trailing newline (the `wheels new` generator templates, the demo app, and the published `starter-app` example). `cfsilent` suppresses only output, not execution, so event code — including `cfheader` — still runs; any output a hook deliberately produces must go through the view or `renderText()` rather than being written directly. **Existing apps:** these files are app-owned (`app/events/*.cfm`), so a framework upgrade does not touch them — if `renderText()` of XML (or any byte-exact response) shows leading blank lines, wrap each `app/events/*.cfm` placeholder in `<cfsilent>…</cfsilent>` with no trailing newline, or delete the empty placeholders you don't use. ([#3882](https://github.com/wheels-dev/wheels/issues/3882))
