- The Wheels CLI now validates the names and values it turns into paths and commands. `wheels deploy` accepts a version (`--version`/`--release`, `rollback <version>`) and a destination only as 1-128 letters, digits, dots, underscores or hyphens, and writes audit log entries quoted. Deploy config load also validates the app and accessory images and every server and accessory host, and service, role and accessory names no longer accept a trailing line feed. Values resolved from `.kamal/secrets`, and any `${VAR}` interpolated into `env.clear`, are redacted from every dry-run and printed deploy command and from remote-failure messages; loading a config that interpolates into `env.clear` warns and recommends `env.secret`, because `env.clear` values travel on the `docker run` command line of every host. `wheels deploy init` creates `.kamal/secrets` owner-only (0600), adds it to `.gitignore`, never overwrites an existing one, and its template recommends `$(cmd)` and `${VAR}` lookups instead of literal values. `wheels packages` accepts only plain package names, resolves every install, removal and cache path directly under `vendor/` or the cache directory, and requires `--yes` for `remove`. Package tarballs are extracted into a staging directory and moved into `vendor/<name>/` only when they contain exactly that one directory with a `package.json` and no links; a `--force` reinstall keeps the installed package until the new one has downloaded and verified. `wheels generate` validates every name it writes into generated code (model, controller, action, view, helper and helper function, migration, route, test, policy, `generate auth` model and `generate admin` model, plus the names `generate admin` reads back from model introspection) and refuses to write any file outside the project, including through an existing symlinked file or directory; `wheels destroy` likewise refuses to delete or rewrite through a symlink that points outside the project. Model, table, property and association names (`--belongsTo`/`--hasMany`/`--hasOne`) and property types must be plain identifiers (letters, digits and underscores, starting with a letter, up to 128 characters), enum values may also contain hyphens, and `wheels new` accepts an app name only as letters, digits, underscores and hyphens starting with a letter. Route names may also contain hyphens, and hyphens in migration and property names become underscores (`create-users-table` → `create_users_table`, `display-name` → `display_name`) with a note. Scaffolded and admin views now HTML-encode record data: `wheels generate scaffold` printed the record's display field (for example the title) unencoded in the show page's `<h1>` and other fields unencoded on the index page, so a record holding markup ran it in the browser of anyone viewing it. `wheels generate admin` printed its index and show fields outside `<cfoutput>` (as literal text) and unencoded. In apps already generated with `wheels generate scaffold`, wrap the `<h1>` value in `app/views/<plural>/show.cfm` and the field values in `app/views/<plural>/index.cfm` in `encodeForHTML()`, for example `<h1>#encodeForHTML(post.title)#</h1>`. Regenerate admin views with `wheels generate admin <Model> --force`. `wheels generate --dry-run` (including `generate admin`) now creates no directories and writes no files, and the error for a path outside the project no longer shows absolute paths. With the RustCFML engine, `wheels stop`, `wheels start` and the server status check only act on the recorded process when it is still this project's RustCFML server: after a crash left the state file behind, a reused process ID could belong to an unrelated program, which `wheels stop` killed. A recorded process that is no longer running is forgotten; one that is running but isn't this project's RustCFML server is kept and reported by process ID on `wheels stop` and status, and `wheels start` replaces the record. `wheels destroy` names are now checked like `wheels generate` names (a quote or `../` in the name used to end up in the generated drop-table migration).
