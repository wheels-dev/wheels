- **Breaking:** an absolute URL's `http`/`https` scheme (`urlFor(onlyPath=false)`, asset URLs, anything through `$prependUrl`) now honours the client-controlled `X-Forwarded-Proto` header **only** when `set(trustProxyHeaders=true)` is enabled — matching `isSecure()`. In 4.1.x the header set the scheme regardless of the opt-in, so an app not behind a trusted proxy could be induced to emit `https://` absolute URLs from a spoofed header. The real socket TLS state (`SERVER_PORT_SECURE`) still always wins, unconditionally. **Apps behind a trusted TLS-terminating reverse proxy must set `set(trustProxyHeaders=true)`** before upgrading, or their absolute URLs will fall back to `http://`. The one-time deprecation warning added in 4.1.2 ([#3835](https://github.com/wheels-dev/wheels/pull/3835)) is removed. ([#3836](https://github.com/wheels-dev/wheels/issues/3836))
