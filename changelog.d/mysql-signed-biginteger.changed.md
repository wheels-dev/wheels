- On MySQL, `t.bigInteger()` now creates a signed `BIGINT`, like every other database, instead of `BIGINT UNSIGNED`, so the column accepts negative values and validates as an integer (it used to bind as a decimal and accept fractions). Existing columns are unchanged, and `changeColumn()` keeps a column's current signedness. `t.bigInteger()` and `t.integer()` take a new `unsigned = true` option (MySQL only; ignored elsewhere) for a foreign key to an existing unsigned id, which MySQL otherwise rejects as incompatible (#4121)
