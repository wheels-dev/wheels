- A SQLite column declared `BIGINT` (or `INT8`) and an Oracle `NUMBER(11..19, 0)` column (what `t.bigInteger()` creates on Oracle) are now typed `cf_sql_bigint`, so their 64-bit values bind correctly on Adobe ColdFusion, and `migrate diff` no longer reports a spurious `integer` to `biginteger` change for a SQLite `BIGINT` column. Wheels' own `t.bigInteger()` still creates `INTEGER` on SQLite, which stays 32-bit (#4086)
