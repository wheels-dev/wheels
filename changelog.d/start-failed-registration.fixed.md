- After a failed `wheels start` (for example a port that is already in use), the next `wheels start` no longer refuses with "registered to a different project: <unknown>". The failed start left a registration folder that names no project; it is now treated as left over and cleaned. `wheels start` also exits non-zero when it refuses to run, both outside a Wheels project and when the server name is registered to another project, so scripts and CI can tell.
