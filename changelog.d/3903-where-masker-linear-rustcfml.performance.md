- The WHERE-clause literal scanner (`$maskWhereLiterals`, run by every dynamic finder, key finder, chainable query-builder call and uniqueness validation) is now linear on every engine. It previously walked the string one character at a time with `Mid()`, which costs O(index) on RustCFML, so a long bound value — or one with many quotes, or a large `IN` list — was O(n²): a 30,000-character value took ~620ms and 100,000 characters ~22s. It now reads the string once into a character array and walks that with O(1) indexing on the engines whose `REMatch` round-trips the input faithfully (Lucee, Adobe, RustCFML), and falls back to a single-pass `Find()`-jump scan on engines where it does not (BoxLang drops whitespace matches). The character-array path builds its short ODBC-date lookahead window inline rather than passing the whole array to a helper, because Adobe CF copies an array argument by value on every call, which would reintroduce O(n²) there. Such values now bind in linear time on every supported engine (#3903)
