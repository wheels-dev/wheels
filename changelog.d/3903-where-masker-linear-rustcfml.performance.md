- The WHERE-clause literal scanner (`$maskWhereLiterals`, run by every dynamic finder, key finder, chainable query-builder call and uniqueness validation) is now linear on RustCFML. It previously walked the string one character at a time with `Mid()`, which costs O(index) on RustCFML, so a long bound value — or one with many quotes, or a large `IN` list — was O(n²): a 30,000-character value took ~620ms and 100,000 characters ~22s. It now reads the string in a single pass and accumulates its output in a CFML array (avoiding the per-index `Mid`, the O(length) Java `StringBuilder.append`, and the O(start) `ArraySlice` that are each quadratic on RustCFML), binding such values in linear time on every engine (#3903)
