- An immediate `wheels test` re-run after a timed-out run no longer collides with the abandoned run still executing server-side. The core (`/wheels/core/tests`) and app (`/wheels/app/tests`) runners used to treat any request arriving mid-run as a re-entrant sub-request and skip their shared lock, so two suites ran at once against the same test database. An overlapping run now waits on the lock and then runs normally. Only sub-requests that echo the in-progress run's token (`wheelsTestRun`) skip the lock. The CLI's timeout message now says the abandoned run is still executing (#3683)
