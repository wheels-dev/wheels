- On SQLite and H2, boolean columns created by migrations (`t.boolean()`, `addColumn(columnType="boolean")`) are now real boolean columns on the model. SQLite created them as `INTEGER` and H2 as `TINYINT(1)`, so the model treated them as integers: automatic validation rejected `true` and `"true"` with "is not a number", and a validated `save()` failed. The migrators now emit `BOOLEAN`, which both adapters read as a boolean, so `true`, `"true"` and `"false"` pass automatic validation and save. This applies to new columns only. Existing `INTEGER` / `TINYINT` boolean columns keep the previous behaviour until a migration converts them, which keeps the stored 1/0 values (on SQLite it rebuilds the table): `changeColumn(table="posts", columnName="published", columnType="boolean");`. The new definition replaces the old one, so pass `default` and `allowNull` again if the column had them (#3870)
