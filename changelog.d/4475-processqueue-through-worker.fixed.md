- `Job.processQueue()` now runs jobs through the job worker, so the in-app path the guide documents is as safe as `wheels jobs work`. Every call first reaps jobs a dead worker left in `processing`, which it never did before. Each job is claimed with its own class's timeout recorded as `claimTimeout`, so a server polling with a shorter timeout no longer reaps it while it runs. Jobs still run with their own timeout, as before. The new optional `processQueue(timeout = n)` caps it. `queue` accepts a comma-delimited list. ([#4475](https://github.com/wheels-dev/wheels/issues/4475))
