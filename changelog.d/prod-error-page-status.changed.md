- Production error pages (`showErrorInformation` off, the default outside development) now return the correct HTTP status for Wheels errors — `404` for a client-triggerable `Wheels.*NotFound` / `ActionNotAllowed`, `403` for `NotAuthorized` / an invalid CSRF token, `406` for `FormatNotAcceptable` — instead of `500` for every error. The status classification previously ran only on the development (`showErrorInformation` on) rendering path (follows #3075, which fixed the same mapping for development)
