- `wheels deploy` and `wheels deploy setup` now build and push the image before deploying it, as the guides describe. They log in to the registry on this machine and on every host (the password from `.kamal/secrets` travels only on stdin), run `docker buildx build --push`, then pull on the hosts. Pass `--skip-push` when the image for that version is already pushed. If no registry password resolves, the login is skipped with a warning
- kamal-proxy now receives the proxy `host` (`--host`) and `ssl` (`--tls`) settings and the health-check interval, and the health-check interval and timeout are sent as durations (`3s`); TLS and host-based routing were silently dropped before
- `wheels deploy rollback` sends the proxy cutover only to roles that run kamal-proxy, and stops the other versions on every host, so a rollback no longer fails on worker hosts or leaves old and restored containers running side by side
- `--destination=<name>` now fails when `config/deploy.<name>.yml` does not exist, instead of silently deploying the base configuration
