- The background-job stale-processing reaper now reaps each job on **the timeout of the worker that claimed it**, not the polling worker's. The claiming worker records its `timeout` in a new `wheels_jobs.claimTimeout` column (added to the table automatically, including to tables created before this change — probed on every `$ensureJobTable`, never a cached flag), and `checkTimeouts` builds each row's grace window from that value. Workers configured with **different `timeout` values can now share a queue** — a short-timeout worker won't reap a job a longer-timeout worker is still legitimately running. A row with no recorded `claimTimeout` (claimed before this change, or on a database where the column can't be added) falls back to the polling worker's timeout, so nothing breaks. Builds on #3888/#3984. ([#3989](https://github.com/wheels-dev/wheels/issues/3989))
