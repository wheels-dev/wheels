- Model: `upsertAll()` no longer overwrites the `createdAt` of an existing row when a record conflicts on `uniqueBy`. The framework-stamped create timestamp was included in the `ON CONFLICT` / `ON DUPLICATE KEY` / `MERGE` update clause, so every upsert that hit an existing row reset its `createdAt` to now; it is now only written on insert while `updatedAt` is still refreshed. A `createdAt` you put in the records yourself is still written on conflict. H2's `MERGE ... KEY` form rewrites every column and is unchanged.
