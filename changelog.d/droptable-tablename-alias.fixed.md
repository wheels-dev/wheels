- `wheels destroy <model>` no longer generates a drop-table migration that fails with "The parameter [name] to function [dropTable] is required": the template now emits `dropTable(name=...)`, and `Migration.dropTable()` accepts `tableName` as an alias of `name`, so migrations already generated by earlier `wheels destroy` runs now migrate without edits
- The `down()` of the migration from `wheels generate snippets soft-delete` no longer calls `removeIndex()` with an unsupported `columnNames` argument; it passes the explicit `indexName` that `up()` creates
