- IP-based debug access (`set(allowIPBasedDebugAccess=true)` with `debugAccessIPs`) now grants the debug GUI and error details to the allowed client's own request only. It used to switch `showErrorInformation`, `showDebugInformation` and `enablePublicComponent` on in the shared `application.wheels` scope for the length of that request, so a concurrent request from any other client could render its error page with full exception detail. The grant now lives in the request scope (`$applyIPDebugAccess()`), and every framework check reads it through `$get()`. Apps with the setting off (the default) are unaffected. **Apps that use IP-based debug access must also update `public/Application.cfc`:** in `onRequestStart()`, replace the `// IP-based access to public Component/debug GUI` block (the `debugIPAccess` bookkeeping and the `// Conditional override for allowed IPs` `if` that follows it; in apps generated by `wheels new` 4.x, the body of `$applyDebugIpAccessOverrides()` and its call) with `application.wo.$applyIPDebugAccess();`. In `onRequestEnd()`, replace `application.wheels.showDebugInformation &&` with `application.wo.$get("showDebugInformation") &&`. Until you make that edit, upgrading alone still protects you: Wheels snapshots these three flags at application start and serves the snapshot (plus the per-request grant) for them, ignoring the per-request writes the old block makes to the shared scope, and logs a one-time warning to update `Application.cfc`. The bundled debug-bar template is also gated on the per-request grant, so a concurrent request never sees another client's debug bar.
