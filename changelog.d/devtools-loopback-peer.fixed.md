- The `/wheels/*` development tools (info, routes, docs, test runners, packages, the deprecated HTTP MCP endpoint, …) now require the request's socket peer (`REMOTE_ADDR`) to be a loopback address, and are refused outright in the `production` environment. A dev server reached through Docker port publishing, where requests arrive from the Docker gateway, can allow specific peers with `set(devToolsAllowedRemoteAddresses="172.17.0.1")` (exact IPv4/IPv6 addresses or IPv4 CIDR ranges; honoured in development and testing only); publish the port on `127.0.0.1` when you do. **Behaviour change** for Docker-hosted development: `/wheels/*` returns 403 from the host until the gateway address is listed. The dev tools and `/wheels/cli` now treat only IP literals as loopback (a zone-scoped IPv6 loopback included); host names in `X-Forwarded-For` are not resolved.
