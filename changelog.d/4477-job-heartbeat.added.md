- Background jobs can call `heartbeat()` from inside `perform()` to signal that they are still running. The stale-job reaper now measures from the latest heartbeat (`COALESCE(heartbeatAt, updatedAt)`), so a long job that heartbeats more often than its timeout is no longer reaped and run a second time. A heartbeat after the job's claim was reaped and re-issued throws `Wheels.Job.Fenced`, telling the old attempt to stop. Each new claim clears the previous attempt's heartbeat. `wheels_jobs` gains a nullable `heartbeatAt` column, added to existing tables automatically (never inside a transaction); without it, `heartbeat()` renews `updatedAt` instead. ([#4477](https://github.com/wheels-dev/wheels/issues/4477))
- Jobs gain `this.idempotent` (default `true`). After a reap, a job is retried only when its class is idempotent, which is today's behaviour. A class with `this.idempotent = false` is not re-run: the reaped attempt ends with the new status `interrupted`, counted by `queueStats()` and `JobWorker.getStats()` and purgeable with `purge(status = "interrupted")`. ([#4477](https://github.com/wheels-dev/wheels/issues/4477))
