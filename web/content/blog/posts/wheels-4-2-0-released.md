Wheels 4.2.0 is out. It's a minor release on the 4.x line: **background jobs you can run across several servers, with schedules, heartbeats, unique and exclusive jobs, and a drain for deploys; `afterCommit` and `afterRollback` callbacks with savepoints and transaction-scoped locks; exact numbers and long IN lists on more databases; new helpers and test assertions; faster requests; and fixes for six security advisories.** It's available on Homebrew, Scoop, apt, yum/dnf and ForgeBox now, and we recommend upgrading.

Full notes: [GitHub Release v4.2.0](https://github.com/wheels-dev/wheels/releases/tag/v4.2.0) · [CHANGELOG](https://github.com/wheels-dev/wheels/blob/main/CHANGELOG.md)

## Security fixes

<!-- PRIVATE until the advisories publish: do not share this section before then. -->

4.2.0 includes fixes for six advisories:

- **Nested properties let a form update, reassign or delete another record's child rows** ([GHSA-6979-65wv-7pxq](https://github.com/wheels-dev/wheels/security/advisories/GHSA-6979-65wv-7pxq)). Nested properties now only update or delete child rows that belong to the record being saved, and a child's foreign key always comes from the parent's saved key. `hasManyCheckBox()` matches posted keys on a surrogate-`id` join model's foreign keys, so unchecking a box can no longer delete an unrelated join row.
- **Scope chains are ignored by `findByKey()` and `exists(key=)`** ([GHSA-2qh9-qcxq-f8qc](https://github.com/wheels-dev/wheels/security/advisories/GHSA-2qh9-qcxq-f8qc)). `findByKey()`, `exists(key=...)`, `updateByKey()` and `deleteByKey()` now combine the key with an incoming scope chain, query builder or `where` argument instead of replacing it, so a key outside the scope matches nothing.
- **Development tools under `/wheels/*` reachable by remote clients when the public component is enabled** ([GHSA-6v6c-p375-vxw9](https://github.com/wheels-dev/wheels/security/advisories/GHSA-6v6c-p375-vxw9)). The `/wheels/*` tools now require the socket peer (`REMOTE_ADDR`) to be a loopback address, and are refused outright in production. Docker-hosted development can allow the gateway with `devToolsAllowedRemoteAddresses`.
- **Any client can switch a request into the isolated test application context** ([GHSA-xcj9-wm25-4cg4](https://github.com/wheels-dev/wheels/security/advisories/GHSA-xcj9-wm25-4cg4)). The test application is selected only in development and testing, and the test-context header or cookie must carry a per-process runner secret and come from a loopback client. App test runs now default to the `<datasource>_test` database and refuse to run without it.
- **Quote-only escaping of inline literals on MySQL and MariaDB** ([GHSA-mvr9-2h5x-w6cq](https://github.com/wheels-dev/wheels/security/advisories/GHSA-mvr9-2h5x-w6cq)). A string value Wheels writes into the SQL text instead of binding it is now written as a hex literal when it contains a backslash, so it reads the same whatever the `sql_mode`.
- **Path containment checks compare paths case-insensitively on case-sensitive filesystems** ([GHSA-m63x-8m98-225v](https://github.com/wheels-dev/wheels/security/advisories/GHSA-m63x-8m98-225v)). Path guards (database dumps, zip extraction, package mappings, dev-UI assets, offline docs) now compare canonical paths exactly through a shared `wheels.PathGuard` helper, and `wheels test --filter` uses the same rule.

Three more hardening changes are listed under Security in the release notes: `LocalDisk` storage validates object keys per path segment, apps generated by `wheels deploy init` read `WHEELS_ENV` instead of running in development mode, and a per-tenant `config` override can no longer switch on `showDebugInformation` or `enablePublicComponent`.

The test database default and the `/wheels/*` loopback rule can need setup; see "If you're upgrading" below.

## Background jobs

- **Schedules.** Define recurring jobs in `config/schedules.cfm` with cron expressions (with time zones) or intervals. Each slot is enqueued once however many servers check, and normal job processing runs them, so no separate scheduler is needed ([#4481](https://github.com/wheels-dev/wheels/issues/4481)).
- **Heartbeats and fencing.** A long job can call `heartbeat()` so it isn't reaped and run twice, and a reaped attempt can no longer overwrite the attempt that replaced it ([#4477](https://github.com/wheels-dev/wheels/issues/4477), [#4476](https://github.com/wheels-dev/wheels/issues/4476), [#4502](https://github.com/wheels-dev/wheels/issues/4502)).
- **Unique and exclusive jobs.** `enqueue(uniqueKey=...)` writes one job per key, even when enqueues race ([#4478](https://github.com/wheels-dev/wheels/issues/4478)). `this.exclusive = true` or a concurrency key keeps a second run from starting on any server ([#4479](https://github.com/wheels-dev/wheels/issues/4479)).
- **Per-host caps and drain.** `jobsMaxConcurrentPerHost` caps one server's running jobs, and `wheels jobs drain --wait` stops a server taking new jobs until its running ones finish ([#4480](https://github.com/wheels-dev/wheels/issues/4480)).
- **Lifecycle hooks.** `beforePerform`, `afterPerform`, `onSuccess` and `onFailure`, plus an app-wide `jobsOnFailure` hook; `perform()`'s return value is now stored ([#4483](https://github.com/wheels-dev/wheels/issues/4483)).
- **Running jobs without a worker.** A token-gated `/wheels/jobs/tick` route lets a scheduled task or cron run jobs inside the app server ([#4482](https://github.com/wheels-dev/wheels/issues/4482)).
- **CLI.** `wheels jobs install` writes a migration for the job tables ([#4484](https://github.com/wheels-dev/wheels/issues/4484)). `wheels jobs enqueue`, `wheels jobs tick` and `wheels jobs work --stop-when-empty` are new, and `wheels jobs work` runs each job for its own timeout ([#4517](https://github.com/wheels-dev/wheels/issues/4517)).

## Transactions and callbacks

- **`afterCommit` and `afterRollback`.** These model callbacks run only once the Wheels-managed transaction commits or rolls back, the place to enqueue a job or send mail. `savedChanges()` and friends tell an `afterCommit` what the save wrote ([#3934](https://github.com/wheels-dev/wheels/pull/3934)).
- **Savepoints.** `transaction="savepoint"` runs a method as a nested unit that rolls back only its own writes while the outer transaction carries on ([#3958](https://github.com/wheels-dev/wheels/issues/3958), [#4068](https://github.com/wheels-dev/wheels/issues/4068)).
- **Isolation.** A `transactionIsolation` setting sets the default level for the transactions Wheels opens ([#4059](https://github.com/wheels-dev/wheels/issues/4059)).
- **Transaction-scoped advisory locks.** `withAdvisoryLock(transaction = true)` pins the lock, the callback and the release to one connection ([#4198](https://github.com/wheels-dev/wheels/issues/4198)). `withAdvisoryLock()` also keeps a second caller out on Lucee and BoxLang ([#4197](https://github.com/wheels-dev/wheels/issues/4197)) and works on SQL Server outside a transaction ([#4220](https://github.com/wheels-dev/wheels/issues/4220)).
- **Transactional enqueue.** A job enqueued in a transaction on another datasource is written when that transaction commits; `transactional=false` writes it after the transaction ends either way.

## Models and queries

- **Wide numbers are exact.** `DECIMAL` values with more than 15 significant digits on PostgreSQL, SQL Server, MySQL and CockroachDB under Lucee and BoxLang ([#4172](https://github.com/wheels-dev/wheels/issues/4172)), and Oracle whole numbers beyond 64 bits ([#4162](https://github.com/wheels-dev/wheels/issues/4162)), are stored and matched exactly. Oracle `NUMBER(38)` ids above 2,147,483,647 bind as 64-bit integers ([#4089](https://github.com/wheels-dev/wheels/issues/4089)).
- **Long IN lists.** On SQL Server 2016+, a query whose IN lists exceed the 2097-parameter limit now runs, with every value still bound ([#4103](https://github.com/wheels-dev/wheels/issues/4103), [#4318](https://github.com/wheels-dev/wheels/issues/4318)). Oracle 19c and earlier split lists over 1000 values ([#3906](https://github.com/wheels-dev/wheels/issues/3906)).
- **Soft deletes.** Soft-deleting a record no longer hard-deletes or unlinks `dependent=` children a restore would need ([#4370](https://github.com/wheels-dev/wheels/issues/4370)); `softDelete=false` is always a real delete ([#4371](https://github.com/wheels-dev/wheels/issues/4371)); and `reload()` throws `Wheels.RecordNotFound` for a missing row instead of blanking the object ([#4372](https://github.com/wheels-dev/wheels/issues/4372)).
- **Migrations run one at a time** across instances sharing a database, under a lease lock; `wheels migrate unlock` shows who holds it ([#4134](https://github.com/wheels-dev/wheels/issues/4134), [#4209](https://github.com/wheels-dev/wheels/issues/4209)).

## New helpers and test tools

- **`isSafeRedirectUrl(url)`** checks a return-to URL by the same rule `redirectTo(url=…)` applies ([#4217](https://github.com/wheels-dev/wheels/issues/4217)).
- **`appCacheFetch()`** and the other `appCache*` functions cache your own computed values without touching the action, page, partial or query caches ([#4388](https://github.com/wheels-dev/wheels/pull/4388)).
- **`escapeForLike()`** escapes `LIKE` wildcards in a search term ([#4355](https://github.com/wheels-dev/wheels/pull/4355)).
- **Query assertions.** `assertQueries()`, `assertNoQueries()` and `assertQueriesMatch()` count the SQL statements a call sends ([#4357](https://github.com/wheels-dev/wheels/pull/4357)).
- **`strictArguments`** reports arguments a framework declaration doesn't know, such as `foreign_key` or `orderby`; it warns in development by default ([#4393](https://github.com/wheels-dev/wheels/pull/4393)).
- **`wheels lookup <query>`** searches the API reference and guides offline, also as an MCP tool ([#4342](https://github.com/wheels-dev/wheels/pull/4342)).
- **`travelTo()`** freezes the framework clock in specs ([#4387](https://github.com/wheels-dev/wheels/pull/4387)), and `$testClient()` now sends CSRF tokens the way a browser does.

## Faster requests

- **Route matching** scans only the routes that can match a request's method and first two path segments; which route matches is unchanged ([#4183](https://github.com/wheels-dev/wheels/pull/4183)).
- **Controller integration** is worked out once per controller class, cutting per-instance setup from 0.58 ms to 0.33 ms on Lucee 7 and from 4.8 ms to 1.4 ms on RustCFML ([#4149](https://github.com/wheels-dev/wheels/issues/4149)).
- **`linkTo()` and `URLFor()`** do less work per call on JVM engines, with byte-for-byte identical output ([#4151](https://github.com/wheels-dev/wheels/issues/4151)). `pluralize()` and `singularize()` cache their results ([#4150](https://github.com/wheels-dev/wheels/issues/4150)).

## CLI and deploy

- **Migrations in deploys.** `migrate: true` in `config/deploy.yml` runs migrations once, on one host, before any host cuts over ([#4063](https://github.com/wheels-dev/wheels/issues/4063)). App containers can mount `volumes:` ([#4018](https://github.com/wheels-dev/wheels/issues/4018)), and the `boot:` block is applied ([#3925](https://github.com/wheels-dev/wheels/issues/3925)).
- **Dev servers listen on `127.0.0.1`**; use `--host 0.0.0.0` to reach one from another device.
- **`wheels new` apps commit `vendor/`**, so a fresh clone has the framework.

## If you're upgrading

These changes can need an edit in your app or environment:

- **Test database.** App tests need a `<datasource>_test` datasource and `WHEELS_ENV` set to `development` or `testing`; or pass `wheels test --no-test-db`.
- **Docker-hosted development.** `/wheels/*` returns 403 from the host until the gateway is listed in `devToolsAllowedRemoteAddresses`.
- **`config/environment.cfm`** should read `WHEELS_ENV`; apps generated earlier hardcode development ([#3946](https://github.com/wheels-dev/wheels/issues/3946)).
- **Behind a TLS proxy**, set `trustProxyHeaders=true`, or absolute URLs fall back to `http://` ([#3836](https://github.com/wheels-dev/wheels/issues/3836)).
- **`findAll(returnAs="structs")`** returns an array; replace `StructCount()` and key loops ([#4003](https://github.com/wheels-dev/wheels/issues/4003)).
- **Empty strings in `where`** bind as `''`, not NULL, including in `updateAll()` and `deleteAll()` ([#4055](https://github.com/wheels-dev/wheels/issues/4055)).
- **`enqueue()`** throws `Wheels.Job.EnqueueFailed` instead of returning `persisted: false`.
- **Validation `condition` / `unless`** resolves bare names and rejects `is`, `and` and `or` on the `this.` path ([#3928](https://github.com/wheels-dev/wheels/issues/3928), [#3964](https://github.com/wheels-dev/wheels/issues/3964)).
- **Accessory `port:`** in `wheels deploy` must name a bind address ([#4067](https://github.com/wheels-dev/wheels/issues/4067)).
- **Actions named `renderNotFound` or `isSafeRedirectUrl`** must be renamed.
- **App-owned files.** `public/Application.cfc` and `app/events/*.cfm` need template edits ([#4470](https://github.com/wheels-dev/wheels/issues/4470), [#3882](https://github.com/wheels-dev/wheels/issues/3882)).

The [4.1 to 4.2 upgrade guide](https://guides.wheels.dev/v4-2-0/upgrading/4x-1-to-4x-2/) lists every edit and behaviour change. Upgrade the CLI first, then run `wheels upgrade check --to=4.2.0` in each app; it names the edits your app is missing. `wheels upgrade apply` swaps `vendor/wheels/`. Happy shipping.
