The first-time deploy verb. Runs the full `wheels deploy` flow and also boots `kamal-proxy` and every declared accessory. Use it once per environment; after that, plain `wheels deploy` is enough.

## Synopsis

```txt title="
wheels deploy setup [--release=<v>] [--destination=<name>] [--dry-run]
```

## Flags

Same as [`wheels deploy`](/v4-2-0/command-line-tools/commands/deploy/deploy/).

## Behavior

`setup` first creates the `kamal` network on each accessory host and boots every accessory declared in `deploy.yml` (`docker run`, plus an audit entry), then runs the same flow as [`wheels deploy`](/v4-2-0/command-line-tools/commands/deploy/deploy/), which starts or boots `kamal-proxy`. On a fresh host, the first `wheels deploy setup` is slower than subsequent deploys because `docker pull` fetches every base image.

Expected preconditions:

- Docker is installed on every host. Run [`wheels deploy bootstrap`](/v4-2-0/command-line-tools/commands/deploy/server/bootstrap/) first if not.
- Registry credentials resolve in `.kamal/secrets`.
- `ssh.user` has passwordless `sudo` (or is `root`).

## Examples

```bash title="illustrative — requires Docker/Kamal environment"
wheels deploy setup
wheels deploy setup --destination=staging
```
