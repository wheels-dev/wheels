Print the fully-resolved `deploy.yml` config as YAML. Mustache interpolation is expanded; destination overlays are merged. Makes no network calls.

## Synopsis

```txt title="
wheels deploy config [--destination=<name>] [--config=<path>]
```

## Flags

| Flag | Description |
|------|-------------|
| `--destination=<name>` | Overlay `deploy.<name>.yml` before printing. |
| `--config=<path>` | Override `config/deploy.yml`. |

## Output

Prints the resolved config as YAML: `service`, `image`, `servers` (hosts per role), `registry`, `proxy`, `env`, `accessories`, `ssh` and `builder`. Secret values never appear: `env.secret` and `registry.password` list only the key names `.kamal/secrets` supplies, and a value resolved from `.kamal/secrets` into `env.clear` is redacted.

```yaml title="example output (abridged)"
service: myapp
image: myorg/myapp
servers:
  web:
    - 192.0.2.10
registry:
  server: ghcr.io
  username: myorg
  password:
    - REGISTRY_PASSWORD
proxy:
  host: app.example.com
  ssl: true
  app_port: 8888
env:
  clear:
    DB_HOST: db.internal
  secret:
    - WHEELS_RELOAD_PASSWORD
```

Per-role options are not emitted.

## When to use

- Verify `--destination` overlays apply the keys you expect.
- Confirm `{{env.*}}` resolves to the right values.
- Diff against `kamal config` during a migration from Ruby Kamal.

## Example

```bash title="illustrative"
wheels deploy config --destination=staging
```
